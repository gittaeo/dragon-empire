# 세 밤 — 시드 기반 웨이브 제안

2026-11-21 · Codex → Claude · 설계안, 수치와 플레이 시간은 미검증

목표는 낮에 예보된 두 방향과 선택한 방어막이 밤의 전술에 영향을 주는 것이다. 기존 1·2·3밤의 웨이브 수 4·5·6, 웨이브당 적 수 5·6·7, 사냥꾼 0·1·2, 간격 20·18·16초와 속도 18·21·24를 첫 실험의 총량 기준으로 유지한다. 방향·등장 순서만 바꾸고 총 적 수와 첫 밤 사냥꾼 0을 보존한다.

## 패턴 4종

| 패턴 | 등장 | 구성 | 의도 |
|---|---|---|---|
| 한 방향 집중 | 1~3밤 | A,A,B,A 또는 B,B,A,B | 방어막이 놓인 쪽을 확인하고 반대편 우선 대응. 예보에 두 방향을 계속 표시한다. |
| 양방향 교차 | 1~3밤 | A,B,A,B 반복 | 가장 단순한 기본형. 첫 밤에 우선 제공한다. |
| 사냥꾼 호위 | 2~3밤 | 해당 파의 기존 사냥꾼 수만큼 추격자, 나머지는 탑 돌진 | 플레이어 공격과 탑 방어의 선택. 사냥꾼을 추가 생성하지 않는다. |
| 마지막 파 돌진 | 2~3밤 | 마지막 파의 같은 적 수를 한 방향에 출현, 속도 ×1.15 | 마지막 압박. 평소와 다른 속도는 웨이브 시작 때 텍스트와 색상으로 예고한다. |

A/B는 그날 낮에 표시한 `S.dirs[0/1]`이다. 어떤 패턴도 예보 밖 방향으로 생성하지 않는다. 호위와 마지막 돌진은 방향 패턴에 붙이는 수정자로, 1밤에는 둘 다 적용하지 않는다. 마지막 속도 배율은 선택 가설이며 이동 경로·지형 문제 또는 난이도 증가가 보이면 1.0으로 컷한다. 첫 밤 4파는 A·B를 각각 최소 한 번 포함한다.

## 데이터 계약 (의사 코드)

```js
// 현재 NIGHT_PLAN(n)의 숫자 속성은 유지하여 기존 소비자와 호환한다.
NIGHT_PLAN(n) => ({waves, size, interval, speed, hunters});
buildWaves({night, runSeed, dirs}) => ({
  version: 1, seed: runSeed, pattern: 'alternate',
  waves: [
    {index: 0, dir: dirs[0].id, count: 5, hunters: 0,
     speedMultiplier: 1, modifier: null},
    // 나머지도 같은 형태. count는 사냥꾼 포함 전체 수.
  ],
});
```

구현은 `NIGHT_PLAN(n)`에서 기준을 읽고 `buildWaves`가 각 밤 시작에 한 번 결과를 만든다. 웨이브 생성기는 `count - hunters`명의 탑 습격자와 `hunters`명의 플레이어 추격자를 만든다. 기존 `S.waveI`·HUD는 배열 길이로 대체하고, 탑 방향별 방어막 소모는 습격자의 실제 출생 방향 `dir`을 사용한다. 각 파의 위치·거리·속도 지터까지 재현하려면 모두 별도 시드 PRNG에서 뽑고 `Math.random()`을 섞지 않는다.

## 시드와 재현

- 새 판에 32비트 정수 `runSeed`를 한 번 만든다. 밤별 PRNG는 버전 고정 믹싱 함수로 `(runSeed, night, 'forecast'|'pattern'|'spawn')` 각각 독립 생성한다. 정확한 PRNG 및 문자열 해시 알고리즘은 구현 시 명시·고정한다.
- 예보를 먼저 고정하고 같은 밤의 패턴을 확정한다. 파생 랜덤 스트림을 분리해 이펙트·적 처치 순서가 예보나 후속 웨이브를 바꾸지 않게 한다.
- QA용 URL `?mode=nights&seed=1234`는 선택 입력으로 제안하며 정수 범위를 검증한다. 결과 화면 또는 테스트 로그에 seed와 패턴 버전을 기록해 재현한다. 기존 최고 기록 저장 형식은 하위 호환한다.
- 승리 후 다시 도전은 새 시드, 명시 seed가 있는 QA URL은 같은 시드로 시작한다. 이 시드는 중간 저장이나 멀티플레이 동기화를 뜻하지 않는다.

## 검증과 전달

- [ ] 같은 seed·버전·밤·예보는 같은 배열, 수많은 seed에서 다른 패턴도 발생.
- [ ] 모든 파의 방향은 예보된 A/B, 첫 밤에는 양쪽 등장 및 hunters=0, 모든 파에서 `0 ≤ hunters < count`, 수량·간격 합계가 기준 유지.
- [ ] 예보·붉은 기둥·생성 방향·방어막 방향이 동일하고 첫/마지막 파 인덱스 및 소모 경계가 정확하다.
- [ ] 패턴 예고, 사냥꾼과 습격자의 구별, 마지막 파 효과, 화살표 가림을 화면과 실제 조작으로 확인한다.
- [ ] seed별 완주 시간·최저 탑 HP·피해·방어막 잔량을 기록한다. 사람/모바일 실측 전 수치는 확정하지 않는다.
- [ ] 보스 시작은 마지막 파 적 전체 정리 후 1회, 패배·재시작·일시정지 시 웨이브가 중복되지 않는다.

세 밤 코드 연결과 게임 UI 수정은 Claude 담당. 이 문서는 구현이나 난이도 검증을 의미하지 않는다.
