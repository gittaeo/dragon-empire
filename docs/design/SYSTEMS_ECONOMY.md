## 0. 한 줄 결론

> **집은 주민을 만들고, 주민은 막사에서 병사가 되거나 아침에 일꾼으로 자재를 번다.**
> "병사로 쓸까, 돈으로 쓸까"가 매일 아침의 핵심 선택이고, 2단계 건물의 열쇠(숨결 파편)는 **용이 직접 잡은 적에서만** 나온다.

현재 문제(코드 기준): 집 = `income: {branch:1, stone:1}` 뿐 → 플레이어 눈에 "보이지 않는 숫자"라 의미가 없다. 자원 3종(가지4·돌3·파편2/일)은 종류만 많고 선택을 만들지 못한다. 망루가 유일한 '싸우는 건물'이다.

## 1. 건물 확정안

### 1.1 쓰는 것 / 빼는 것

| 건물 | 결정 | 이유 |
|---|---|---|
| 집 | **유지 · 역할 교체** | 수입 → **인구(주민)**. 병사의 원천이자 일꾼 |
| 막사 | **신규 (MVP)** | 주민을 병사로 바꾸는 유일한 건물. 사용자 요청 "병사가 나오게" 직접 응답 |
| 목책 | 유지 | 방향 선택(예보 2방향)의 핵심. 병사가 서는 '전선' 위치를 정의 |
| 망루 | 유지 + 2단계 갈래 | 공중 대응. 갈래(석궁/저격)는 파편 필요 |
| 풍향탑(수리) | 유지 | 패배 조건. 수리는 자재 싱크 |
| 성문 | **자르기 → 목책에 흡수** | 목책 4방향과 기능이 겹침. 별도 개폐 로직은 1개월에 비용 대비 효과 낮음. 목책 중앙에 '문 모양' 외형만 |
| 농장(밭) | **나중(P1)** | "수입 크지만 취약"은 좋은 긴장이나, 지상 적이 건물을 공격하는 AI가 먼저 있어야 의미가 생김 |
| 광산 | **자르기** | 일꾼 주민이 같은 역할(수입). 건물 종류만 늘림 |

### 1.2 건물 표 (자원: 자재 M / 숨결 파편 F — 2장 참조)

| 건물 (자리 수) | 역할 한 줄 | 1단계 비용 → 효과 | 2단계 비용 → 효과 | 갈래 |
|---|---|---|---|---|
| **집** (3) | 주민을 늘린다 | 3M → 주민 **+2** | 3M·1F → 주민 **+2 추가(총 4)** · 창문 불빛 2배 | 없음 |
| **막사** (1) | 주민을 병사로 훈련 | 5M → 병사 정원 **4** (창병) | 4M·2F → 아래 갈래 중 택1 (판 동안 고정) | **창병대**: 정원 6, 병사 HP 40→60 / **궁수대**: 정원 4, 대공 사격 사거리 45m |
| **목책** (4방향) | 그 방향 돌진을 막고 병사의 전선이 된다 | 2M → 내구 **5** | 3M·1F → 내구 **9** + 병사 배치 시 병사 피해 +20% (방벽 엄호) | 없음 |
| **망루** (4) | 공중 적 자동 사격 | 4M → 피해 14 / 1.4초 / 120m (현행 유지) | 3M·2F → 갈래 택1 | **석궁**: 피해 10 / 0.6초 / 100m (물량) · **저격**: 피해 45 / 3초 / 170m, HP 높은 적 우선 |
| **풍향탑 수리** | 탑 HP 회복 | 2M → +25 (최대 100) | — | — |

설계 메모
- 1단계 집은 파편을 요구하지 않는다 → 첫날 반드시 '병사 루트'를 열 수 있음.
- 막사는 **1개만**: 병사 상한을 막사 정원으로 묶어 유닛 수 상한(성능)을 데이터로 보장. 최대 병사 = 6(창병대) 또는 4(궁수대).
- 망루 1단계에서 파편을 뺐다(현행 `shard:1` 삭제). 파편은 "2단계 = 용이 싸운 대가"로만 쓴다.

### 1.3 시너지 구조 (건물 간 연결)

```
 집 ──(주민)──┬─→ 막사 정원만큼 → 병사 (밤: 목책 앞 전선)
              └─→ 남는 주민 = 일꾼 → 아침 자재 +1/명
 목책 ── 병사가 서는 위치를 정함(예보 방향 목책 앞에 자동 집결). 목책 없는 방향에 병사 배치 = 탑 앞 최후선
 망루 ── 공중 처리. 병사(창병)가 못 닿는 고도를 담당
 용   ── 처치 → 파편 → 모든 2단계 / 포효(R)로 병사 강화 / 사냥꾼(rider) 전담
```

**병사 수 = min(주민, 막사 정원)**, **일꾼 = 주민 − 병사**. 플레이어는 아침에 막사에서 E → 슬라이더 대신 **[병사 +1] [병사 −1]** 두 버튼으로 배분(기본값: 정원까지 전부 병사). 이것이 "집 = 병사 / 집 = 돈" 사이의 진짜 선택이다.

예: 집 3채(1단계) = 주민 6. 막사 1단계 정원 4 → 병사 4 + 일꾼 2(아침 +2M). 막사 없으면 일꾼 6(+6M) — 탐욕 루트.

## 2. 자원 구조

### 2.1 결정: 3종 → 2종

| 현재 | 변경 | 이유 |
|---|---|---|
| 나뭇가지 + 돌 | **자재(M)** 하나로 통합 | 가지/돌 구분이 만드는 결정이 없음(둘 다 항상 같이 부족). 비용 표기가 한 숫자로 줄어 패드 라벨 가독성↑. 노드 외형은 가지·돌 2종을 그대로 써도 둘 다 자재 1로 계산 |
| 숨결 파편 | **유지 · 출처를 용 처치로 한정** | 희소 자원 = 2단계 열쇠. "용이 싸워야 기지가 강해진다" 연결 |
| (코인화) | **하지 않음** | 줍는 재료가 낮 활동의 근거(인간형 걷기). 코인 단일화는 Thronefall 복제로 보이고 줍기 의미를 없앰 |

코드 영향(참고, Codex 소유): `DAY_ITEMS`를 `[['material', N], ['shard', 0~1]]`로, `BUILD.*.cost`를 `{material, shard}`로. 기존 세이브의 branch+stone은 합산 이관.

### 2.2 수급 수치

| 출처 | 양 | 비고 |
|---|---|---|
| 낮 채집 (자재 노드) | 1낮 **10M** · 2낮 **8M** · 3낮 **8M** | 노드 수 고정(무한 채집 불가). 1낮이 많은 이유: 첫 건설 2~3개 보장 |
| 낮 채집 (파편 노드) | 1낮만 **1F** | 2단계 하나를 미리 맛보게 하려는 장치 아님 → 첫 집/목책 2단계 1개 가능 |
| 아침 기본 수입 | 풍향탑 **+2M** | 아무것도 안 지어도 최소 수입 |
| 아침 일꾼 수입 | 일꾼 1명당 **+1M** | 집 → 돈 경로 |
| 밤 처치 보상 | **용이 직접 처치한 적 5마리당 1F, 밤당 상한 3F** | 망루·병사 처치는 0. 처치 수는 결과 화면에 '용 처치 / 건물 처치' 분리 표시 |
| 보스 웨이브 사냥꾼 처치 | 사냥꾼 1마리 = 2마리로 계산 | 용을 노리는 적을 용이 상대할 이유 |
| 남은 자원 | 전부 이월 | 저축 선택지 |

현행 '8마리당 파편 1'(nights.js startDay)은 건물 처치도 셀 수 있으므로 **용 처치 한정 + 5마리/상한3**으로 바꾼다.

### 2.3 총예산 vs 총수요 (긴장의 크기)

- 3일 자재 총수입: 채집 26 + 탑 기본 4(아침 2회) + 일꾼 0~10 = **30~40M**, 파편 1 + 밤1·2 최대 6 = **최대 7F**.
- 전부 짓는 데 필요한 양: 집 3×(3+3)=18M·3F, 막사 9M·2F, 목책 4×(2+3)=20M·4F, 망루 4×(4+3)=28M·8F → **75M·17F**.
- 즉 **전체의 약 절반**만 가능. 매일 "무엇을 포기할지"가 남는다.

## 3. 파괴·재건·사망 규칙

| 대상 | 밤 중 | 아침 | MVP 여부 |
|---|---|---|---|
| 목책 | 돌진자 1마리 충돌 = 내구 −1, 사슬 기사 공격 2초당 −1. 0이면 무너짐(그 방향 무방비) | **무료 완전 복구** (현행 유지) | MVP |
| 망루·막사·집 | **파괴되지 않음** | — | MVP |
| 망루·집 (P1) | 사슬 기사가 목책을 넘으면 가장 가까운 집/밭 공격(HP 60). 0 → 불탐 | 무료 재건, **단 그 아침 해당 건물 효과 없음**(집이면 그 주민 일꾼 수입 0·병사 부활 안 함) | 나중 |
| 병사 | HP 40(창병대 60). 0 → 쓰러짐(그 밤 복귀 없음) | **전원 부활**(주민은 죽지 않음 — 병사는 '부상' 표현) | MVP |
| 풍향탑 | 돌진 1회 −8, 보스 등불 −12 | 자동 회복 없음. 수리(2M)만 | MVP |

이유: 1개월 범위에서 건물 파괴·재건 시각화(잔해, 재건 연출)는 비용이 큼. 목책만 '소모'시키면 "밤마다 부서지고 아침에 다시 선다" 리듬을 이미 얻는다(현행 fortify.js 재사용). 병사 영구 사망은 3밤 짧은 판에서 회복 불가 스노우볼을 만들기 때문에 넣지 않는다.

## 4. "손 놓으면 이기는" 방지 장치

| # | 장치 | 수치 |
|---|---|---|
| 1 | **자동 방어 DPS 상한**: 최적 건설 + 입력 0인 봇은 **2밤 3파 이전에 패배**해야 한다 | Codex 회귀 테스트 항목으로 고정. 실패 시 망루 연사·병사 피해부터 하향 |
| 2 | **파편 = 용 처치 전용** | 용이 싸우지 않으면 2단계 0개. 3밤 기지가 1단계에 묶임 |
| 3 | **사냥꾼(rider)은 용만 노리고, 망루 우선순위 최하** | 망루는 돌진형 우선(현행). 사냥꾼을 방치하면 용 HP 손실 |
| 4 | **병사는 고도 14m 이하만 공격**(궁수대 45m) | 등불 나방은 45~75m로 접근 → 마지막 하강 구간에서만 병사가 닿음. 고공 구간은 용·망루 몫 |
| 5 | **예보 2방향 vs 망루 사각** | 망루 자리 4개는 대각선(π/4). 한 방향을 망루 2개가 겹쳐 덮으려면 8M+ 필요 → 반대 방향은 용이 가야 함 |
| 6 | **용의 포효(R) — 병사 강화** | 용이 목책 60m 내에서 R: 그 방향 병사 피해 +50%, 8초, 쿨다운 25초. 병사 루트의 화력은 용이 와야 완성됨 |
| 7 | **보스 루세르나의 탑 등불** | 현행 유지: 자동 방어 공격 불가(`NIGHTS_BUILD.md` 기본 정책). 용만 요격 가능 |

목표 체감 비율(밤 처치 기준): 용 50~60% / 망루 25~35% / 병사 10~20%. 결과 화면에 세 숫자를 그대로 보여준다.

| 결정 | 순간 | 감정 |

## 7. 쟁점 (다른 역할과 조율 필요)

1. **[전투·웨이브] 지상 적 도입 여부** — 창병의 존재 이유는 사슬 기사(지상, HP 60/140/240)다. 전투 역할이 "전부 공중 유지"를 택하면 창병은 나방의 마지막 하강 구간(≤14m)에서만 싸워 존재감이 약하다. 제안: 2밤부터 파마다 사슬 기사 1~2마리(예보 표시 포함). 1밤은 공중만(교육).
2. **[전투·웨이브] 나방 비행 고도** — 현재 `p.y = ground + 45~75`, 탑 접근 시 `ground+8`까지 하강. 병사 교전 구간이 목책(반경 25~34m) 근처에서 생기려면 "목책 50m 이내 진입 시 고도 ≤12m로 하강" 규칙이 필요. 적 기동 변경은 전투 역할 소관.
3. **[전투·웨이브] 처치 보상 귀속** — 망루·병사 처치를 파편에서 빼면 "건물에 투자할수록 보상이 줄어드는" 역설이 생긴다. 내 판단: 의도된 것(용 참여 강제). 반대 시 대안은 건물 처치 = 자재 0.2/마리.
4. **[전투·웨이브] 자동 방어 상한 수치** — 망루 피해 14/1.4초는 밤1 나방(HP 18)을 2발에 처리 → 밤1은 망루 2개면 거의 자동. 밤1을 교육으로 남길지, 자동 상한을 밤1부터 적용할지 결정 필요.
5. **[UX·레벨] 패드 수와 배치** — 막사 자리 1개 추가 필요(현재 11자리: 목책4·망루4·집3). 제안 위치: 탑 남쪽 r=14. 병사 집결 경로가 패드·목책 비계와 겹치지 않는지 레벨 확인.
6. **[UX·레벨] 병사/일꾼 배분 UI** — 버튼 2개(+1/−1)로 충분한지, 아니면 자동(정원까지 병사)만 두고 배분을 P1로 미룰지. 터치 조작 고려.
7. **[UX·레벨] 자원 통합 표기** — 줍는 노드는 가지·돌 2외형인데 HUD는 '자재' 하나. 혼동 테스트 필요. 아이콘: 나무+돌 묶음.
8. **[스토리] 주민의 정체** — 탑 주변에 누가 사는가? 세라 외 주민 설정, 병사가 '용의 백성'인지 '피난민'인지. 3밤 대관(엠페러) 장면에 병사들이 무릎 꿇는 연출 가능 여부.
9. **[스토리·전투] 병사 사망 표현** — '쓰러짐→아침 부활'을 부상으로 볼지 사망으로 볼지. 등급·톤 문제.
10. **[Codex/성능] 유닛 상한** — 병사 최대 6 + 적 동시 최대(밤3 7×2파 겹침 ≈ 14) + 투사체. 병사 AI는 경로 탐색 없이 "목책 앞 고정 슬롯 ↔ 반경 8m 내 적에게 직선 이동"으로 제한해야 1개월 안에 가능.
