# 풍향탑의 세 밤 v2 — 기술·QA 리드 검토

2026-11-22 · Codex → 디렉터·각 역할 · **토론안, 구현 승인 또는 밸런스 확정 아님**

브리프와 1단계 코드(`base.js`, `nights.js`, `fortify.js`, `ground.js`, `game.js`)를 기준으로 작성했다. 참고 영상 해석은 공통 브리프를 전달받은 것이며 영상을 직접 분석한 결과는 아니다. 인원·FPS·비용 숫자는 측정 전 가설이다. 새 규칙은 디렉터 결정 전에 구현하지 않는다.

## 질문 1 — 집과 방어 시설의 역할

집 1채에 아침 수입과 **눈에 보이는 수비병 2명**을 연결하는 최소안을 권한다. 집이 살아 있으면 수입을 얻고 다음 날 병사 2명을 보충한다. 기존 11개 패드와 자원 3종을 재사용하고 막사·농장·광산·성문은 MVP에서 추가하지 않는다. 병사는 집 주변이 아닌 해당 방면에 정해진 방어 위치로 나타나야 집의 결과가 한눈에 보인다. 플레이어가 집을 지은 뒤 두 병사가 달려 나와 전선에 서면 선택의 결과를 바로 이해한다. 집 효과 표시에는 수입, 병사 수, 재생성 조건을 모두 명시한다.

기술적 주의: 기존 집은 수입만 계산하며 건물 HP나 파괴 상태는 없다. 병사 생성과 유지·사망·집 파괴 관계는 별도 상태가 필요하다. 병력으로 수비와 수입을 둘 다 받으므로 집이 유일한 정답이 되지 않도록 비용/효과를 실제 플레이로 조정한다. 건물 상태는 `pad.level`, `hp`, `destroyed`, `homeSoldierIds`처럼 명시하고, 시각 메시와 게임 상태를 분리한다. 수비병 전용 막사 요구가 강하면 집 1개를 막사로 전환하는 단일 선택으로 대체하고 자동 수입을 중복 부여하지 않는다.

## 질문 2 — 지상 적·목책·병사

지상 사슬 기사 1종을 넣되 **길찾기 없는 고정 경로**부터 검증한다. 방향별 2~3개 waypoint(출현→목책→탑)를 고정하고, 매 프레임 XZ를 이동한 후 `terrain.heightAt(x,z)`로 높이를 구한다. 통과 가능한 길 4개를 제작 시점에 실제 지형에서 점검한다. 지상 적은 앞에 살아 있는 목책과 전선 병사를 공격하고, 목책 파괴 후 탑 또는 경로상의 집을 공격한다. 공중 등불은 용·망루가 상대하고 목책을 무시한다. 이는 기존 `raidStep`의 공중 목책 차단 규칙을 바꾸는 **명시적 제안**이며 전환 시 기존 테스트·예보·안내문을 함께 변경해야 한다.

병사는 자유 경로 탐색 없이 방면별 2개 고정 슬롯에 배치하고 `idle → acquire → attack → dead`로 움직인다. 공격은 우선 짧은 사거리 투사체/창 찌르기 중 하나만 사용하며, 피해는 기존 `damageEnemy` 경로를 통해 적용한다. 사거리·지상/공중 대상 필터를 명시해 지상 병사가 공중 적을 원거리에서 공격하지 않도록 한다. 기사 GLB가 실제로 걷는 리깅이 있는지 미확인: 없으면 임시 이동/흔들림으로 검증하고, 승인되지 않은 신규 에셋·리깅 비용을 예산으로 가정하지 않는다. 병사가 길을 막는 장면은 싸움의 가치를 보여주지만 충돌 물리·개별 병력 지휘·navmesh는 제외한다.

## 질문 3 — 용과 자동 방어의 분담

목표는 병사/목책이 **시간을 벌고**, 용이 둘 중 취약 방향과 공중 위협을 선택하는 것이다. 방치 승리가 나오는지를 seed별 자동 방치 테스트로 관찰하되, 일부러 무조건 패배하도록 정답을 고정하지 않는다. 첫째 밤 지상 1방향·공중 1방향을 동시 또는 짧은 간격으로 예고하고, 탑 근접 위협과 병사 피해를 분명하게 표시한다. 용이 개입했을 때 적 제거·탑 HP 차이가 보이면 성취감으로 이어진다. 플레이어 실력·시야·사운드에 대한 가정은 실제 플레이로 검증한다.

## 질문 4 — 낮 경제와 선택

기존 하루 채집량 가지 4·돌 3·파편 2를 출발점으로 한다. 예시 비용(가지/돌/파편): 집 2/1/0, 목책 2/1/0, 망루 2/2/1. 첫날 세 시설의 합은 6/4/1이므로 수입 없이 모두 지을 수 없어 첫 선택이 생긴다. 단, 실제 잔액·수리비·2일 수입은 기존 구현과 각 역할의 최종 표를 기준으로 재산정한다. 첫 구매 시점, 채집 경로 길이, 각 비용을 화면에 보여주고, 재료 부족 시 필요한 개수와 대안을 표시한다. 낮은 무제한이므로 노드 재생성이나 반복 수입을 막지 않으면 선택 압박이 사라지는지 확인한다. 영구 저장 슬롯과 세 밤의 판별 자원은 혼용하지 않는다.

## 질문 5 — 3밤 곡선과 보스

| 시점 | 기술·QA용 가설 | 사용자에게 보여 줄 변화 |
|---|---|---|
| 1밤 | 2방향, 지상 4 + 공중 4; 동시 활성 적 한도 12 | 집 병사가 지상 경로를 저지하는 동안 용이 공중 경로를 지킴 |
| 2밤 | 지상 6 + 공중 6; 2파 이상으로 나눔 | 손상된 전선과 재건의 의미 확인 |
| 3밤 | 지상 8 + 공중 8; 2방향 교차, 탱커는 기존 기사 HP 변형으로만 실험 | 용이 취약 방향을 선택하고 방어망을 보강 |
| 보스 | 기존 루세르나와 등불 유지, 병사·지상 적 추가 스폰은 기본 중단 | 목표가 보스와 탑 방어에 집중됨 |

총 출현 수와 동시 활성 수를 구분한다. 현재 `NIGHT_PLAN`과 수치가 달라지는 안이므로 실제 난이도는 미검증이다. 예보·스폰은 동일한 seed 기반 파형 데이터를 사용해 방향·종류·수량이 실제 결과와 일치해야 한다. 아침 수입은 **밤 종료 시 살아남은 집** 기준으로 1회 산정 → 다음 낮 진입 시 재건 → 병사 보충 순으로 한다. 집 파괴 직후 무료 재건하면 손실이 무의미해지므로 수입 판정 전에 복구하지 않는다. 집이 부서져도 이월 레벨은 보존하는 가설이다. 목책 자동 복구·병사 보충·집 수입 각각 시점을 HUD에서 설명한다.

## 질문 6 — 판 밖 진행

현재 최고 기록과 시드를 우선 활용하고 새 영구 업그레이드 트리는 제외한다. 재도전은 다른 건물 선택·예보 seed로 동기를 만든다. 영구 보상은 기존 장기 성장/슬롯 설계와 충돌할 수 있어 사용자가 장기적 영구 성장을 원한다는 사실을 유지하되, 이번 1개월 세 밤 MVP에 구현 여부는 별도 결정한다. 저장 버전 변경이 필요하다면 기존 슬롯과 판별 기록을 분리하고 손상·구버전 복구 및 새 게임을 테스트한다.

## 질문 7 — 한 달 MVP·절단 기준

1주: 고정 지상 경로 1개·집 1채·병사 2명·목책 1개를 잇는 세로 슬라이스. 2주: 4방향 경로·피해/파괴/수입·예보. 3주: 3밤·보스 연결, 소리/시각 피드백, 새 플레이어 테스트. 4주: 버그·성능·패키징과 수정 여유. 이는 **작업일 가정일 뿐 일정 보장 아님**. 기존 용 전투와 출시 빌드를 항상 구동 가능하게 유지한다.

1주 말에 지상 경로에서 유닛이 지면 아래로 빠지거나 목책 공격·보충이 정상 동작하지 않으면 지상군 확장을 멈추고 단일 경로만 남긴다. 2주 말에 프레임 예산을 지속 초과하거나 시각적으로 집→병사 관계가 전달되지 않으면 병사 수·표현을 줄이고 분기, 별도 경제 시설과 지휘 기능은 자른다. 사용자에게 보여줄 핵심은 **집을 지음 → 병사 등장 → 적을 붙잡음 → 다음 날 결과**다. 미해결 상태에서 자동화를 추가해 넘어가지 않는다.

## 구조·성능·검증 계약

- 고정 상한 초기 제안: 적 동시 24(지상 12·공중 12), 병사 8(집 최대 3채면 기본 6), 망루 4, 투사체 40, 효과 파티클 별도 150. 상한 도달 시 웨이브 출현은 취소하지 말고 지연하고 실제 예보 총수는 유지한다. 기준은 기획용 상한이며 현재 FPS를 측정한 것은 아니다.
- 목표 실측: 데스크톱/저사양 실제 대상 기기에서 60초 전투 p95 프레임 시간 33.3ms 이하(30FPS 목표); 적 24·병사 8·투사체 40의 최악 장면, 해상도·기기·브라우저 기록. GPU 시간 포함 전체 렌더 측정과 부하 변화 전후 비교. 기기 부족 시 미검증으로 보고한다.
- 리소스: geometry/material 공유와 적·병사·탄환 풀을 고려한다. 공유 리소스를 유닛 사망마다 dispose하지 않는다. 새 상태에서 리스타트·씬 정리 시 중복 메시, 타이머, 이벤트 리스너, 투사체 누수가 없는지 확인한다. 기존 적 템플릿은 공유 구조다.
- 업데이트 순서 가설: 입력/일시정지 → 웨이브 스폰 → 지상 이동·교전 → 용/자동 방어 피해 → 사망·파괴 확정 → 승패 판정 → 밤 종료 수입 기록 → 다음 낮 재건. 같은 프레임 탑 파괴와 보스 처치의 우선순위는 기존 패배 우선 계약 유지 여부를 디렉터가 명시한다.
- 단위 테스트: 자원 차감 원자성·부족 시 무변화, 집 파괴와 수입 판정·1회 지급, 병사 상한/중복 보충, 목책 파괴/복구, 예보와 실제 스폰 일치(다수 seed), 지상/공중 대상 선택, 같은 프레임 승패, 재시작/저장 격리.
- 브라우저 회귀: 기존 4개 스모크를 유지·수정하며 집 건설→병사 등장→지상 적과 교전→집 피격/파괴→아침 수입 및 재건→병사 보충을 실제 화면으로 검증. 테스트 위치 이동이나 시간 단축은 명시하고, 가시성은 상태만으로 통과 처리하지 않는다. 별도 사람 손 플레이 3명 이상에서 집의 의미를 설명 없이 이해하는지, 전투 역할과 승패 원인을 관찰한다.
- 계측: 건물별 건설/파괴 시각·수입, 병사 생성/사망/피해, 지상·공중 처치, 탑 최저 HP, 웨이브 출현/실제 수, FPS를 seed와 함께 기록. 개인 정보 없이 로컬 기록만 사용한다.

## 쟁점 — 디렉터 결정 요청

1. 집이 병사와 수입을 함께 주는지, 별도 막사가 필요한지. 둘 다 제공하면 자원 효율과 선택 폭이 무너질 위험.
2. 공중 적이 기존처럼 목책을 소모하는지. 지상 전용으로 바꾸면 기존 공략과 테스트가 바뀌지만 역할은 명료해진다.
3. 집 공격 대상을 고정 경로에서 어떻게 보장할지. 아무 경로에도 없는 집은 무적 수입원이 된다. 경로 슬롯/명시 타깃과 전조를 함께 설계해야 한다.
4. 아침 재건이 공짜인지, 파괴된 집이 해당 밤 수입을 잃는지, 병사가 0명일 때 보충 가능한지.
5. 4주 일정 내 플랫폼 우선순위(PC 브라우저 기준선, 모바일 실측 가능 기기)와 성능 목표.

## 역할별 검토

네 역할의 초안을 읽고 구현 위험·검증 조건·축소안을 아래에 기록했다. 실측 전에는 구현 불가능하다고 단정하지 않는다.

### 스토리·세계관 (`STORY_MEANING.md`, 초안 읽기 기준)

- **범위 초과 위험:** 집마다 인구 누적, 일꾼 채집, 막사 전환, 성문, 망루 주민 배치, 주민 귀가·이동 연출을 동시에 구현하면 AI·배정·경제 상태와 예외 경로가 크게 늘어난다. 1개월 MVP는 집별 병사 고정 생성 + 수입, 고정 슬롯 방어, 1종 지상 적으로 줄이고 막사/일꾼/성문/주민 지휘는 후순위로 제안한다. 집의 의미를 화면으로 보여주는 목표는 보존한다.
- **검증 조건:** “직접 깬 적만 파편 지급”은 자동 망루·병사·용이 같은 적을 공격할 때 처치 귀속 규칙이 필요하다. 마지막 타격 방식은 불쾌한 막타 경쟁을 만들 수 있으므로 귀속 규칙 합의 전 경제 가정으로 사용하지 않는다. 기존 밤 처치 보상은 플레이어 전용이라는 근거가 없다.
- **낮밤 연출:** 주민이 실제 길을 걸어오고 부상자가 귀가하는 장면은 동적 경로가 아닌 짧은 고정 연출 또는 등장 효과로 대체 가능하다. 대관 빛줄기는 집별 최대 3개 시각 효과만 실험하고 기능 보너스는 제외한다.
- **일관성:** 스토리 제안은 사슬 기사 둘째 밤 첫 등장, 기술 초안은 첫 밤 등장이다. 첫 밤 역할 학습과 이야기 전개 중 어느 쪽을 우선할지 디렉터가 결정해야 한다. '마지막 알'과 연맹의 성격 등 기존 세계관 충돌 가능성도 기존 미확정 사항으로 유지한다.

### 시스템·경제 (`SYSTEMS_ECONOMY.md`, 초안 읽기 기준)

- **과대 범위:** 자원 통합·기존 저장 이관, 막사와 주민 배분 UI, 용 처치 귀속, 2종 적, 병사 진형까지를 동시에 MVP로 잡으면 세이브·전투·UX 테스트가 함께 늘어난다. 집→병사와 한 지상 경로를 먼저 검증하고, 기존 가지/돌/파편 유지 및 인원 자동 배분을 기본 축소안으로 제안한다. 자원 이관을 한다면 슬롯별/기존 공용 결정·탐험 모드 보존, 멱등성과 롤백 검증이 필수다.
- **설계 내부 충돌:** 1낮 파편 1개가 있는데 “용이 싸우지 않으면 2단계 0개”는 성립하지 않는다(집·목책 2단계는 1F). 문서의 1낮 첫 집→주민 2와 다른 구간의 둘째 아침 주민 생성 시점도 확정해야 한다.
- **규칙 충돌:** 표는 공중 돌진 1회 = 목책 내구 −1인데 쟁점은 목책 지상 전용으로 읽힐 수 있다. 공중·지상 분리, 병사의 비행 적 고도 허용 범위를 확정해야 예보와 회귀를 작성할 수 있다. 기존 보스 등불에 대한 자동 방어 불가 주장도 현행 구현과 실제 동작을 코드/브라우저로 먼저 확인해야 한다.
- **테스트 기준:** '입력 0이면 반드시 2밤 3파 전 패배'는 제작 조합·seed·난수·초기 상태가 정의되지 않아 단독 pass/fail로 부적합하다. 여러 명시 조합/seed의 방치 결과와 사람 플레이 결과를 나란히 기록하고 목표 비율은 검증 후 결정한다. 용 처치만 보상은 피해 출처와 막타 귀속이 명시돼야 하며, 다수 공격 동시 사망·중복 지급을 테스트한다.
- **경제 표 검산:** 3낮 이후 수입을 사용할 수 없는 현재 루프에서는 일꾼 전환 시점과 최대 수입의 유효 범위를 구분하고, 건물 파괴를 MVP에서 뺄 경우 '경제 건물을 지켜야 한다'는 위험은 목책 소모/탑 위협으로만 성립한다. 효율 루트 3개는 사람이 실제로 조작·수집하는 시간까지 측정한다.

### 전투·웨이브 (`COMBAT_WAVES.md`, 초안 읽기 기준)

- **과대 범위/성능:** 4주차에 5개 적 유형, 3방향 동시전, 건물 점화, 망루 정지, 포효 버프와 보스 중 지상 추가 웨이브까지 넣으면 각 행동·경고·조합 테스트가 배가된다. 1주차에 지상 기사와 목책·집→병사 한 경로부터 검증하고, 공성꾼·봉화·기수의 건물 정지·보스 지상 웨이브는 모두 후순위로 둔다. '동시 40 적/모바일 50fps'와 GLB 1~3 draw call은 실측치가 아닌 가설이다. 적 상한을 먼저 24로 두고 기기별 p95·GPU 실측 후 증감한다.
- **계약 충돌:** 경제 초안은 밤중 병사 부상→아침에만 복귀지만 전투 초안은 15초마다 재생성한다. 병사 HP도 경제 40, 전투 100이며 집·막사 정원도 다르다. 병사 공격 대상과 사거리도 다르므로 한 계약을 결정한 뒤 단위·브라우저 테스트를 만든다.
- **예보의 실제 수:** 3밤 마지막 파 A/B/C 동시는 기존 두 방향 `forecast`·화살표·결과 통계와 기존 seed 테스트를 바꾼다. 예보와 실제 출현의 공통 계획을 단일 데이터로 만들고, 상한으로 출현을 지연할 때 수량 손실·종료 조건 조기 진입이 없도록 테스트한다.
- **지형/가시성:** 150m 지상 경로의 고도·경사·수면/장애물은 네 방향을 실제 샘플링하기 전 통과로 간주할 수 없다. 바닥에 단순 평면 흙길을 놓으면 지형에 파묻히거나 공중에 뜰 수 있어 지형을 따라 나눈 메시 또는 경로 표식을 우선 실험한다. 방어선과 건설 패드 반경 34/25 차이도 화면 표식으로 연결해야 한다.
- **피해 출처:** `damageEnemy`는 현재 네 번째 인자가 `quiet`이고, 호출자와 사망 함수가 다수라 단순 인자 추가만으로 스킬·충격파·보스/탑 사격 귀속이 완성되지 않는다. 공통 피해 이벤트·마지막 타격 여부, 제거와 처치의 차이를 정의하고 탐험 모드 회귀를 포함해야 한다.
- **보스/범위:** 보스전 100% 플레이어 처리 목표는 기존 망루가 `userData.assault`를 대상 목록으로 받는 코드와 비교해 실제 요격을 먼저 검증해야 한다. 목표 수치와 요구 사항이 부합하는지 결정 전까지 불가능/가능을 단정하지 않는다.

### 레벨·UX (`LEVEL_UX.md`, 초안 읽기 기준)

- **과대 범위:** 16개 패드 재배치·농장·막사 2개·완전한 레이더·7m 월드 카드·홀드 입력·자동 줍기·카메라 시퀀스·자동 착륙을 함께 변경하면 1개월의 기존 회귀와 접근성 확인에 과하다. 11개 패드 유지 + 집의 병사 효과 표시 + 두 방향의 종류/수 예보 + 지상 경로 표식과 위험 경고만 우선한다. 레이더는 실제 전투 가독성이 부족할 때 고정 크기 2D 캔버스로 추가 검토한다.
- **조작·회귀:** 자동 줍기는 기존 E 기반 온보딩/저장/인벤토리와 탐험 모드의 수집 규칙을 바꿀 수 있으므로 세 밤 모드에 격리하고 겹친 다중 노드·인벤토리 가득 참·저장 후 재입장·터치/키보드를 검증해야 한다. 길게 누르기는 취소·포커스 이탈·버튼 릴리스와 기존 한 번 누르기 가이드를 모두 갱신한다. 7m 카드가 2.8m 상호작용의 최근접 대상과 다르게 표시되지 않게 동일 거리 정렬과 동률 처리 계약이 필요하다.
- **충돌·좌표:** 착륙장 이동은 `ground.js` 공용 `PAD` 변경과 세 밤/탐험 모드 초기화 순서 및 저장 복원에 영향을 준다. 고정 지점은 지형 높이, 장애물·채집물·건물의 실제 거리와 드래곤 크기를 샘플링해야 한다. 반경·시간 표는 직선거리이며 경사, 충돌 및 카메라 변화로 측정 전 보장할 수 없다.
- **설계 충돌:** 첫 밤 예보가 북쪽인데 첫 안내가 남문을 먼저 짓게 한다면 사용자는 잘못된 방향에 재료를 쓸 수 있다. 실제 예보 방향으로 첫 건설을 유도하거나 안전한 학습용 재료를 별도로 보장해야 한다. '공중도 목책 차단'은 전투 안의 지상 전용과 충돌하고, 집 4·막사 2·농장은 경제 안의 집 3·막사 1·농장 보류와 충돌한다.
- **출시 전 검증:** 자동 착륙/카메라 강제 이동은 조작 취소와 일시정지·전투 종료 경계, 멀미·터치 가림 검증이 필요하다. 자동 착륙은 MVP에서 보류하고, 최소 1280×720과 360×740 가로·세로 캡처 및 가능하면 실제 모바일에서 조이스틱·전투·예보 겹침을 확인한다. 고정 카메라·연출 시간 6초도 건너뛰기/입력 복귀를 먼저 정의한다.
